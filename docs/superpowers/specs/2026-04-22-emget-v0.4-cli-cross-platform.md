# emget v0.4 — CLI 子命令、跨平台、TUI 滚动、自动构建设计

- **日期**:2026-04-22
- **作者**:mhpsy + Claude (brainstorming 会话)
- **目标读者**:后续实现者
- **上游版本**:v0.3.0 (commit `2661600`)

## 1. 背景与目标

v0.3.0 之后,emget 以纯 TUI 形式运行在 Linux。本版本聚焦四件事:

1. 暴露四个只做纯 CLI 输出的子命令,供外部工具 / 脚本消费
2. 让 Windows 与 macOS 用户开箱可用(配置目录)
3. TUI 列表型屏(结果、剧集、队列)内容溢出时能滚动
4. 在 GitHub 上自动构建多平台二进制,并注入版本信息

GitHub 仓库:`https://github.com/mhpsy/emget.git`。

### 非目标(YAGNI)

- 不做交互式 Wizard(`config init`);配置首次缺失时已有模板写入流程
- 不做 shell 补全生成
- 不做自动更新检查
- 不做 Windows 原生安装器(MSI/Scoop 等),只出 zip 产物

## 2. CLI 子命令

`cmd/emget/main.go` 入口按第一个位置参数分发:

```
emget                  → TUI(默认行为保持不变)
emget tui              → TUI(显式别名)
emget tasks [flags]    → 按分类打印任务
emget clean [flags]    → 清理任务记录
emget config [flags]   → 打印配置路径与内容
emget version          → 打印版本与构建信息
emget help | -h        → 用法
```

实现不引入 cobra / urfave-cli,每个子命令用 `flag.NewFlagSet` + 一个独立文件 `cmd/emget/cmd_<name>.go`。

### 2.1 `emget tasks`

默认按 `status` 分组打印,状态顺序:`downloading → queued → failed → canceled → completed`。

Flags:
- `--status=<name>`:只打印指定状态(支持逗号分隔多个)
- `--format=table|json`:输出格式,默认 `table`
- `--no-color`:关闭 ANSI 颜色(非 tty 时自动开启)

表格列(table 模式):`ID(短8位) | TYPE | NAME | PROGRESS | SIZE | STATUS`。

JSON 模式直接 marshal `[]*downloader.Task`,便于下游解析。

数据源:`state.Store.Load()` → `store.Tasks()`。**不**启动 queue、不启动 emby client、不需要会话。

### 2.2 `emget clean`

默认清空 `state.json`,交互确认 `[y/N]`。

Flags:
- `--completed-only`:只删 `Completed` 状态的任务
- `--failed-only`:只删 `Failed` + `Canceled`
- `--yes` / `-y`:跳过确认

实现加一个 `state.Store.Remove(predicate func(*Task) bool) int` 方法,返回删除数量。`clean` 走这个而不是直接 `Clear()`(`Clear()` 在 v0.3 已存在,继续给 startup recovery 用)。

### 2.3 `emget config`

打印:
1. 配置文件路径(即 `ConfigDir() + config.yaml`)
2. 各个目录路径(config / cache / data)
3. 解析后的配置内容(YAML 序列化)

**密码脱敏**:`Emby.Password` 字段打印成 `****`(即便为空也保持 `****` 以免泄露长度)。

Flags:
- `--paths-only`:只打印路径,不打印内容
- `--raw`:打印原始 YAML 文件而非 parsed 版(不脱敏,加警告前缀 `# WARNING: contains plaintext password`)

### 2.4 `emget version`

格式:

```
emget <version> (commit <sha[:7]>, built <YYYY-MM-DD>)
go<goVersion> <GOOS>/<GOARCH>
```

变量来自 `cmd/emget/version.go` 的 package-level 变量(见 §5)。

## 3. 跨平台目录

替换 `internal/config/paths.go`。新的目录映射:

| 类别 | Linux | macOS | Windows |
|------|-------|-------|---------|
| Config | `$XDG_CONFIG_HOME/emget` 或 `~/.config/emget` | `~/Library/Application Support/emget` | `%AppData%\emget` |
| Cache | `$XDG_CACHE_HOME/emget` 或 `~/.cache/emget` | `~/Library/Caches/emget` | `%LocalAppData%\emget\cache` |
| Data | `$XDG_DATA_HOME/emget` 或 `~/.local/share/emget` | `~/Library/Application Support/emget` | `%AppData%\emget` |

实现策略:
- `ConfigDir()` → `os.UserConfigDir() + "/emget"`
- `CacheDir()` → `os.UserCacheDir() + "/emget"`
- `DataDir()` → 平台分支:
  - Linux:手动读 `XDG_DATA_HOME`,否则 `os.UserHomeDir() + "/.local/share/emget"`
  - Darwin:同 `ConfigDir()`(macOS 里 "持久化用户数据" 惯例就放 Application Support)
  - Windows:同 `ConfigDir()`(AppData 同时承担 config 与 data)
  - 其他 Unix:走 Linux 分支

`expandHome()` 继续支持 `~` 前缀;`filepath.Join` 代替字符串拼接,Windows 分隔符才正确。

**向后兼容**:Linux 用户不受影响(XDG 路径不变)。macOS 老用户(如果有)要手动把 `~/.config/emget` 的文件挪到 `~/Library/Application Support/emget`,这点在 `README` Breaking Changes 里声明。

## 4. TUI 滚动

### 4.1 通用模式

给每个列表型 Model 加:

```go
offset int  // 当前视口顶部对应的 item 索引
```

每次渲染前跑窗口修正:

```go
visible := a.height - headerH - footerH
if s.cursor < s.offset              { s.offset = s.cursor }
if s.cursor >= s.offset + visible   { s.offset = s.cursor - visible + 1 }
```

渲染只遍历 `[offset, offset+visible)`,超出的在首/尾用 `↑ N more` / `↓ N more` 指示。

按键扩展(原有 `↑ / ↓` 保留):
- `PgUp` / `PgDn`:跳半屏
- `Home` / `End`:跳首 / 尾
- 鼠标滚轮:bubbletea 原生不处理,不做

`a.width` / `a.height` 已经被 `app.go` 的 `WindowSizeMsg` 捕获,每个子 Model 的 `View()` 能拿到(通过 Model 上新加的 `width/height` 字段,由 `app.Update` 在 resize 时穿透下去)。

### 4.2 涉及的屏

| 屏 | 文件 | headerH | footerH |
|----|------|---------|---------|
| 搜索结果 | `results.go` | 3(标题+空行+分隔) | 2(提示行+空) |
| 剧集详情 | `detail_series.go` | 4(标题+副标+空+分隔) | 2 |
| 任务队列 | `progress.go` | 3 | 2 |

`search.go`、`startup.go`、`detail_movie.go` 内容短,**不做**滚动(YAGNI)。

### 4.3 Detail Series 特殊处理

该屏本来就有展开/折叠。滚动要按**当前可见行**(已展开的集才算行)计数,不能按季算。具体做法:

在 `View()` 之前先把所有可见行 flatten 成 `[]renderRow`,对 flatten 后的列表做滚动窗口。

## 5. 版本注入

`cmd/emget/version.go`:

```go
package main

var (
    version = "dev"
    commit  = "none"
    date    = "unknown"
)
```

编译时通过 ldflags 注入:

```
go build -ldflags "
  -X main.version=$VERSION
  -X main.commit=$COMMIT
  -X main.date=$DATE
" ./cmd/emget
```

`Makefile` 的 `build` 目标改成读取本地 git 信息:

```make
VERSION := $(shell git describe --tags --always --dirty 2>/dev/null || echo dev)
COMMIT  := $(shell git rev-parse --short HEAD 2>/dev/null || echo none)
DATE    := $(shell date -u +%Y-%m-%d)

build:
	go build -ldflags "-X main.version=$(VERSION) -X main.commit=$(COMMIT) -X main.date=$(DATE)" -o bin/emget ./cmd/emget
```

## 6. GitHub Actions

### 6.1 `.github/workflows/ci.yml`

触发:`push`(任何分支)、`pull_request` → `main`。

```yaml
strategy:
  matrix:
    os: [ubuntu-latest, macos-latest, windows-latest]
```

步骤:
1. checkout
2. setup-go@v5 with `go-version: '1.24'`
3. `go vet ./...`
4. `go test ./...`
5. `go build ./...`

### 6.2 `.github/workflows/release.yml`

触发:tag `v*` push。

用 **goreleaser**(`goreleaser/goreleaser-action@v6`),配置在 `.goreleaser.yml`。

产物:
- `emget_<version>_linux_amd64.tar.gz`
- `emget_<version>_linux_arm64.tar.gz`
- `emget_<version>_darwin_amd64.tar.gz`
- `emget_<version>_darwin_arm64.tar.gz`
- `emget_<version>_windows_amd64.zip`
- `checksums.txt` (sha256)

goreleaser 注入 ldflags:`-X main.version={{.Version}} -X main.commit={{.ShortCommit}} -X main.date={{.Date}}`。

Release notes:由 goreleaser 从 commit log 生成,按 `feat:` / `fix:` 分组。

Permissions:需要 `contents: write` 才能创建 Release。

## 10. 风险与缓解

| 风险 | 缓解 |
|------|------|
| Windows 上 TUI 显示乱(bubbletea 对 Windows Terminal 兼容性) | CI matrix 只验证能 build + test;不 block release。必要时在 README 注明推荐 Windows Terminal |
| goreleaser 配置写错导致 tag 后没产物 | 先 push 一个 `v0.4.0-rc1` pre-release tag 验证,通过再发正式版 |
| 子命令与 TUI 共用 config / state,会不会竞争? | 所有子命令只读状态文件;`clean` 写入,但不会和 TUI 同时跑(用户手工调用)。沿用现有 store 的 mutex,无须额外锁 |
| macOS Data 目录改到 Application Support,老用户数据丢失 | 影响面小(这个项目还没有非 Linux 用户),README 注明一次迁移步骤即可 |

## 11. 完成定义

- 四个子命令 `emget tasks` / `clean` / `config` / `version` 都能在 Linux/macOS/Windows 上正确工作(至少 Linux 本地验证全量,macOS/Windows 通过 CI)
- TUI 在 `results` / `progress` / `detail_series` 三屏超过屏高时能正常滚动,cursor 跟随,顶/底有 `↑ N more` / `↓ N more` 提示
- `make build` 产物 `emget version` 打印含 tag + commit 的信息
- `git push --tags` 后 GitHub Actions 自动构建出 5 个平台产物,release 页可见
- 根 `README.md` 英文更新 + `README.zh-CN.md` 新建
- tag `v0.4.0` 推送
